# PDF自動取得システム 要件定義書

## 概要

指定したWebページを巡回し、PDFファイルを自動収集するシステムを構築する。

特定の分野に限定しない汎用ツールとする。当初の想定用途は、研究費・公募情報の収集である
（Phase3「研究費公募レーダー構想」を参照）。

> 本書は初期の要件を記したもので、実装では次の点が変更・追加されている。
> 現在の仕様は [README](../README.md) を参照。
>
> - 設定ファイルは `config/sites.example.yaml`（サンプル）を `config/sites.yaml` にコピーして使う
> - `robots.txt` で禁止されたページ・PDFは取得しない（`respect_robots`）
> - 取得済みPDFの台帳として `data/index.json` を使う

対象例（設定例。利用前に各サイトの利用規約・robots.txt を確認すること）

- IPA
- JST
- AMED
- NEDO
- 文部科学省
- 経済産業省
- 各大学サイト

取得したPDFはローカルへ保存し、将来的にはAIによる要約・分類まで実施する。

# システム要件

## 機能要件

### 1. URL巡回

設定ファイルに記載されたURLへアクセスする。

例

```yaml
sites:
  - name: IPA
    url: https://www.ipa.go.jp/shiken/mondai-kaiotu/2025r07.html

  - name: JST
    url: https://www.jst.go.jp/souhatsu/call/index.html
```

---

### 2. HTML解析

対象ページのHTMLを取得する。

利用ライブラリ

```python
requests
beautifulsoup4
```

---

### 3. PDFリンク抽出

HTML内の

```html
xxxx.pdf
```

を検出する。

対象

```text
.pdf
.PDF
```

両方対応。

---

### 4. PDFダウンロード

抽出したリンクからPDFを取得する。

要件

- タイムアウト設定
- リトライ機能
- 重複ダウンロード防止

---

### 5. フォルダ自動生成

保存先

```text
data/
```

配下に自動生成

例

```text
data/

├─ IPA
│
├─ JST
│
├─ NEDO
│
└─ AMED
```

---

### 6. 日付管理

取得日ごとにフォルダ作成

例

```text
data/

└─ IPA
    └─ 2026-10-22
```

---

### 7. 重複判定

以下いずれかで判定

- URL
- ファイル名
- SHA256 ハッシュ

推奨

```text
SHA256
```

---

### 8. ログ出力

出力先

```text
logs/
```

形式

```text
2026-10-22 12:00:00

START

DOWNLOAD:
sample.pdf

SUCCESS

END
```
